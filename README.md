# 糖果收纳所

微信颜色排序游戏，支持小程序 Canvas 2D 页面和原生小游戏入口，复用同一套界面、100关数据与存档逻辑。按已确认的奶油色、糖果色与透明收纳盒视觉方向实现，不使用震动，无生产依赖。

## 运行

1. 打开微信开发者工具，导入项目；按自己的账号类型选择小程序或小游戏。
2. 项目目录选择 `D:\project\rust\youxi`。
3. 使用你自己的 AppID；当前配置已保留你填写的 AppID 和小程序模式。真机预览、上传和发布需要相应权限。
4. 当前 `compileType: miniprogram` 由 `app.json` 加载 `pages/game/game`。如果使用小游戏账号，将 `compileType` 改为 `game`，由根目录 `game.js` 启动。

小程序页面使用 Canvas 2D 绘制，原生透明 `view` 点击区域与棋盘及按钮保持同步，操作通过 WXML `bindtap` 进入共享逻辑。页面也保留 Canvas 触摸作为兼容入口。小游戏入口使用全局触摸和可用的鼠标事件。两者都由 `utils/controller.js` 负责玩法和存档。

如果出现 `env: Windows,mg` 且提示找不到 `game.json`，请确认导入的是包含根目录 `game.js`、`game.json` 和 `project.config.json` 的完整目录。修改配置后重新打开项目再编译。仅添加空的 `game.json` 无法运行 WXML 页面。

## AppID 获取与填写

登录 https://mp.weixin.qq.com/ ，选择自己的小游戏账号，在「开发／开发管理 → 开发设置」查看「AppID（小程序 ID）」。如果尚无账号，先在公众平台注册，并按注册界面选择游戏类目。这里使用小游戏账号的 AppID。

项目中的填写位置是根目录 `project.config.json` 的 `appid` 字段。导入微信开发者工具时也应填写同一个 AppID。当前已保留你填写的值，请在自己的后台核对归属；仅凭本地文件无法确认账号身份。登录开发工具的微信需要是对应账号的管理员或开发者。不需要把 AppSecret 填入本项目。

## 玩法规则

- 先点来源盒，再点空盒或顶部同色且有空位的目标盒。
- 一次转移顶部连续同色糖果，以目标剩余容量为限。
- 四颗同色糖果装满一盒后锁定；所有颜色收好即通关。
- 共100关，无时间限制。提供撤销、重开、提示与本地自动存档，不使用震动。
- 第1～10关从4色增加至6色；第11～40关以6～7色交错为主；第41～70关收紧至一个空盒；第71～100关以7～8色综合挑战为主。第15、25等关卡作为轻松关，减少颜色、恢复两个空盒；每十关标记挑战关。
- 100个不同盘面均已精确计算最少步数，并附最优解。一次合法批量转移算一步；选择盒子、无效操作不计步，撤销回退一步。求解仅在开发时执行，手机只加载结果。
- 三星：恰好最少步数通关；两星：超过最少步数1～5步；一星：其余成功通关。选关页显示每关历史最高星级，较慢重玩不会降低已获得的星级。
- 顶部「选关」打开每页20关的旅程页，显示进行中、未解锁和已通关状态，以及每关最佳步数。通过一关自动解锁下一关，已解锁关卡可以重玩。
- 通关保存最佳步数和完成次数，重玩不会清除记录；从结算页撤销再完成不会重复累计次数。所有记录仅保存在本机，清除小程序数据或更换手机不会同步。
- 底部仅保留撤销、提示、重开一排按钮，帮助和选关入口位于顶部；九盒关卡使用三行自适应排列。
- 百关版迁移旧版当前关卡编号并解锁到该关，不伪造通关记录；旧盘面重置为新版关卡。百关版之后切换关卡会分别保留各关盘面和步数，重新打开也能恢复；关卡初始数据变更时对应旧盘面失效。
- 提示在内置解题路径上提供已验证的下一步；偏离该路径后推荐合法动作，不保证最优或最终可解。遇到死局可撤销或重开。
- 恢复存档或切换关卡后撤销历史重新开始；撤销支持当前关卡本次连续游玩所做的步骤。

## 验证

运行 `node tests/run-all.js` 执行八组自动测试：100关唯一性与可解性、独立穷尽验证没有更短解、星级边界及输入兼容、控制器交互、成绩与迁移、四种屏幕下的布局、小程序 Canvas 宿主及原生点击区域、小游戏入口加载和100关最优解三星通关。

`tests/wechat-loader.test.js` 使用只接受 JavaScript 模块的加载器从实际 `game.js` 启动，通过画布触控连续完成100关、点击下一关并验证成绩保存和最终存档恢复。该测试复现过旧版 `require('./levels.json')` 导致的 `levels.json.js` 缺失错误。它模拟模块解析和微信 API，不能代替微信开发者工具及真机验证。

微信开发者工具已连接并验证小程序启动。手机真机的安全区域、触摸反馈和后台恢复仍需单独验收，模拟器及自动测试不能替代真机验证。

本地浏览器辅助预览：运行 `node scripts/preview.js`，打开 `http://127.0.0.1:8790/tests/preview.html`。该预览复用实际 Canvas 绘制代码，模拟微信 API，仅用于界面检查。已检查游戏页、选关首尾页，截图在 `docs/level-select-preview.png`。

## 文件

- `utils/engine.js`：纯逻辑与已验证关卡加载。
- `utils/levels.js`：100个混排关卡、最少步数与最优解，使用 JavaScript 模块；`utils/level-plan.js` 定义难度分段。
- `scripts/build-levels.js` 和 `scripts/exact-solver.js`：离线生成并精确求解。`tests/optimal.test.js` 独立验证每关不存在更短解。
- `game.js`、`game.json`：小游戏入口和配置。
- `utils/canvas-game.js`：小游戏 Canvas 界面、触控和生命周期。
- `utils/controller.js`：共享交互、成绩、星级与存档逻辑。
- `utils/rating.js` 和 `utils/input.js`：评分和小游戏输入兼容。
- `pages/game/`：小程序 Canvas 宿主、原生点击区域和生命周期。
- `docs/game-design.md`：玩法设计。

首版未接入广告、支付、后台、统计或音效。概念图用于视觉方向参考；当前实现使用可适配的程序绘制糖果，而非整张效果图铺底。
