# 糖果收纳所：首版设计

## 目标与平台
交付能导入微信开发者工具运行的原生微信小游戏，使用 Canvas 和 JavaScript，不依赖服务器。以竖屏触控为主。首版用于体验玩法，不包含支付、广告或线上发布。

## 方案比较
1. 糖果颜色排序（推荐）：点击盒子转移顶部连续同色糖果，兼有收纳和消除反馈；美术与内容规模适中。
2. 三物匹配：点击物品进入暂存槽，三件相同物品消除；容易上手，但对遮挡布局和关卡生成要求更高。
3. 毛线排序：按颜色抽取线团完成图案；视觉反馈丰富，但首版动画与素材成本更高。

## 首版玩法
每盒容量四颗糖果，只有顶部糖果可以移动。先点来源盒，再点空盒或顶部同色且有空位的盒子，一次移动可容纳的顶部连续同色糖果。装满四颗同色糖果后，该盒播放完成动画并锁定，作为已收纳成果保留。所有颜色完成收纳即过关。颜色除色相外使用不同符号辅助识别。

提供十个内置关卡，从四种颜色逐步增加到八种颜色，前六关保留两个空盒，后四关保留一个空盒。第7～8关七种颜色，第9～10关八种颜色。开局非空盒全部为满盒混色。关卡通过离线迭代加深搜索验证可解，后四关参考最短解至少24步，最后两关至少28步，避免在手机上运行求解器。允许撤销、重开、提示与下一关；无时间限制或失败倒计时。无可移动步骤时提示撤销或重开。新版存档与最初简单版隔离；关卡颜色或盒子数量变化时重新开始该关。

## 界面
奶油色背景、薄荷绿操作强调色、柔和糖果色和圆角透明收纳盒。顶部显示关卡和已完成颜色数，中间为盒子棋盘，底部仅保留一排操作按钮。问号入口移至顶部，九盒关卡使用三行排列并自适应盒子高度。通关显示结算弹层。不使用震动，不保留震动开关。适配安全区域与窄屏。

## 数据与结构
独立纯 JavaScript 游戏逻辑负责移动合法性、胜利判定、撤销和提示；页面负责交互、动画及渲染。使用本地存储保存当前关卡、盘面与设置，读取失败回退到第一关。提示只推荐合法动作，不保证最短解。

## 验收
验证合法与非法移动、容量限制、连续同色批量转移、完成锁定、撤销恢复、全部关卡可解以及存档恢复。提供导入说明，开发者工具使用测试 AppID；真机与发布需用户自己的 AppID。交付时区分已执行的逻辑测试与需要开发者工具完成的界面验证。
